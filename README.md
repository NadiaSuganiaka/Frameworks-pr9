# ПР9 · StudyFlow · Доступ ADMIN через RolesGuard

**Дисципліна:** Серверні фреймворки та REST API. **Група:** КНК-23.
**Тривалість:** окрема пара 90 хвилин; обов’язкова частина 40–45 хвилин. **Максимум: 3 бали.**

## Результат

`GET /api/v1/admin/users`: без токена → 401; із валідним STUDENT-токеном → 403; із ADMIN-токеном → 200 і список.

Тут ви використовуєте механізми NestJS: metadata, Reflector, ExecutionContext та порядок guards. Не реалізуєте повторно збереження даних, CRUD, register/login або перевірку власника ресурсу.

## Що отримуєте

Готовий NestJS 11-проєкт з контролером, двома ролями, JWT guard, декоратором Roles, заготовкою RolesGuard, генератором локальних токенів, запитами та готовою перевіркою. БД і Docker для цієї роботи не потрібні; список користувачів — фіксована навчальна відповідь.

Це незалежний стартовий стан F-P09-start. Навіть після пропуску попередньої пари можна виконати саме поточні TODO. Назва каталогу не означає, що Git-тег вже опубліковано.

## Викладачу до заняття

Node.js 22 LTS рекомендовано (мінімум 20.19). У каталозі стартера: `npm ci`, `npm run tokens`, `npm run dev`. Остання команда компілює код та запускає сервер на 3002. Після редагування зупиніть сервер Ctrl+C і виконайте `npm run dev` знову; автоматичної перезбірки тут немає.

Перевірте `http://localhost:3002/api/v1/health`. Генератор створить `.env.local` із випадковим локальним ключем і `tokens.local.json` із двома **підписаними JWT**, чинними 2 години. Це не рядки «admin/student» замість перевірки підпису. Ключ і токени не надсилайте в журнал або студентський звіт. Оновити прострочені токени: `npm run tokens`; за незміненого ключа перезапуск сервера не потрібний.

Студенти не мають писати JWT-модуль. Ключ у навчальному проєкті не призначений для зовнішнього сервісу; сервер прив’язано до localhost.

## Початковий стан

JwtGuard уже підключений. Без токена буде 401, проте STUDENT **ще помилково отримує 200**, бо роль поки не перевіряється. Ваша задача — усунути цей недолік. `npm run check` до завершення роботи повинен провалитися на сценарії student → 403. Це очікувано.

## 4 кроки — студенту

1. **5–10 хв:** запустіть підготовлений проєкт `npm run dev`; перегляньте `src/auth/roles.decorator.ts` і `role.enum.ts`. У `src/admin.controller.ts` додайте `@Roles(Role.ADMIN)` над `listUsers()` (TODO F1). Реалізація декоратора вже готова.
2. **15 хв:** завершіть `canActivate` у `src/auth/roles.guard.ts` (TODO F2). Reflector уже читає metadata методу, а потім класу. Якщо вимоги до ролей немає — поверніть true. Інакше через `context.switchToHttp().getRequest<AuthRequest>()` отримайте користувача й перевірте, чи має він хоча б одну потрібну роль. Не читайте роль із тіла/довільного заголовка запиту.
3. **5 хв:** у контролері змініть підключення на `@UseGuards(JwtGuard, RolesGuard)` (TODO F3). Спочатку перевіряється JWT й формується `request.user`, потім перевіряється його роль.
4. **10–15 хв:** перезапустіть `npm run dev`, виконайте три сценарії нижче; `npm run typecheck` і `npm run check` мають пройти. Нові тести писати не потрібно.

## Запити

У Postman collection відкрийте вкладку Variables: вставте значення `student` та `admin` з `tokens.local.json` у змінні `studentToken` і `adminToken`. Або підставте їх у `requests.http`. Токен не потрібно передавати як JSON і не можна підміняти просто словом ADMIN.

```http
GET /api/v1/admin/users
```

Без Authorization: `401`. Із `Authorization: Bearer <student>`: `403`. Із `Authorization: Bearer <admin>`: `200`:

```json
[
  {"id":2,"name":"Student Demo","roles":["STUDENT"]},
  {"id":1,"name":"Admin Demo","roles":["ADMIN"]}
]
```

У відповідях 401/403 NestJS може додавати `message`, `error`, `statusCode`; перевіряйте насамперед статус. Невалідний або прострочений токен також → 401, не 403.

`GET /api/v1/me` зі student → 200: автентифікація працює, але це не дає права на admin endpoint. Відсутність @Roles у цьому прикладі означає відсутність **перевірки ролі**, а не автоматичну публічність: JwtGuard працює окремо.

## Що здати

`src/auth/roles.guard.ts`, `src/admin.controller.ts`, готовий `roles.decorator.ts` (для контексту), три відповіді 401/403/200 і заповнений `submission.md`. У прикладах закрийте токени. Достатньо commit/цих файлів; не здавайте node_modules, dist, `.env.local`, `tokens.local.json`.
